# R06 — Self-contained source-read policy

Renderer inputs must be self-contained within their materialized root. Prepared proposal/static input and the separately materialized theme are checked before preprocessing/publication, and the full project is checked again before starting Zola. Links resolving outside the approved input root, into Git administration, through directory cycles, or to missing/special-file targets fail explicitly. Internal file/directory links remain supported. Repeated internal aliases are traversed once, not expanded exponentially.

This deliberately rejects previously tolerated external links by default. It does not grant the entire workspace/home directory readable-input status, and there is no hidden opt-out. Portable relative internal links are recommended: an absolute link back to an original checkout is outside the materialized input and must be rewritten or its data explicitly included. Copying a public asset into tracked input is an explicit admission, unlike automatically dereferencing an external pathname.

Only link-target metadata is consulted before admission, not external file content. Rejected live updates remain in private staging and do not reach Zola's watched tree; subsequent safe input can recover. Fresh build/check/targeted preparation share this boundary. Existing output from a build made with an older permissive tool is not retrospectively certified or scrubbed.

This is source-link read admission, NOT a process sandbox. Build.toml/workspace settings, templates, executable dependencies and custom template helpers remain trusted configuration/code. For arbitrary hostile templates/tools, use an isolated account/container without credentials or sensitive host mounts. Same-user concurrent filesystem replacement and intentionally included ordinary/hard-linked local files are outside this link policy. Preview routing and write containment remain distinct boundaries.

Git clean-filter configuration (`.gitattributes`) must be ordinary files, not links/directories. This narrow configuration restriction applies to fresh and live input alike; it does not remove supported confined asset links.
