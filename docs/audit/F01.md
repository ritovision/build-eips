# F01 — Generated-filesystem containment candidate

Repository-controlled links must not become ancestors of a write/delete operation. Mutation boundaries check each existing path component, reject proposal Markdown links, guard the reserved theme mount, and check generated/source-root overlap. Generated Git directories may not redirect through an external gitdir file. Markdown is replaced through an adjacent temporary file rather than truncating a potentially hard-linked file. Supported leaf asset/theme links are still copied as links; this is not a blanket symlink prohibition.

The supported active-checkout/build layout remains valid when disjoint from tracked source, content and Git metadata. User-selected generated directories remain disposable; this does not convert `clean` into a general safe-directory deletion API.

Regression evidence covers dirty and clean proposal symlinks, theme ancestor symlinks, hard links, overlapping source roots, ordinary builds and the existing theme-link preservation tests. Reproduction fixtures use disposable external-to-build sentinels only.

Threat boundary: deterministic repository-controlled path redirection, not a sandbox against hostile same-user processes racing path replacement. No handle-relative/openat race-proofing claim is made. Windows reparse-point checks are included, but native Windows acceptance remains separate from Linux testing.
