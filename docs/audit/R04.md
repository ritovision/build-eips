# R04 — Shared Git-entry conflict contract

Fresh merges and live sibling admission now call the same mode/kind/object-identity predicate. Live disk identity uses Git's owner-executable normalization and preserves indexed executable mode on platforms whose generated index disables filemode trust. Link blobs use link text, not target bytes; broken links are not mistaken for deletion. Sibling insertion now preserves the mode that was actually compared rather than converting every entry to regular Blob.

The real fresh/live differential cases cover bytes, executable mode and symlink/regular transitions, conflict recovery and deletion while the fixed sibling contribution remains. Local forks and fixed-startup sibling semantics are unchanged. Native Windows filesystem acceptance remains distinct from Linux testing.


Final parity testing also covered Git clean filters. Physical CRLF worktree bytes can have the same Git blob identity as LF sibling bytes. The live check now uses libgit2's path-hinted blob writer, matching index clean-filter behavior; link text is still hashed verbatim. Tracked .gitattributes changes/deletions are staged privately before identity checks and the repository attribute context is reopened. A real test proves CRLF startup, changed/deleted attribute-policy conflicts and recovery. Raw-byte equality is no longer substituted for Git object identity.

Git attribute configuration is an explicit exception to asset-link support: `.gitattributes` must be an ordinary file. Both fresh admission and live staging reject linked/directory attribute files rather than allowing filter evaluation to follow them. This prevents the new filter-aware identity call from reading an external configuration target; ordinary confined asset links remain supported. Missing attribute paths below a replacing regular file are treated as absent by the shared tree inspector.
