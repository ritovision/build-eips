# F07 — Atomic initial checkout publication

Fresh clones are built in a private temporary directory next to their destination. A theme is checked out at its initial manifest pin before publication. Only a successfully completed checkout is renamed into place. All initializers sharing a destination parent take `.build-eips-init.lock`; the file remains but its operating-system lock is released on process exit. A killed initializer may leave a `.build-eips-init-*` scratch directory, never a falsely completed `theme/`.

A genuinely existing usable checkout is preserved without resetting its HEAD or dirty edits. Pre-existing plain directories are still rejected. Ordinary clone failures now use the same staging boundary as theme clones.

Tests cover invalid-pin retries, completed historical pinning, preservation of developer edits, and refusing unrelated existing directories. Native Windows and process-kill acceptance must be reported separately from Linux unit results. This does not claim protection from hostile same-user processes bypassing the initializer lock.
