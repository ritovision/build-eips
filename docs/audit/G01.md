# G01 — Cross-platform case-collision rejection

Tracked input must have one deterministic path namespace across supported developer platforms. Git object trees are case-sensitive, while common Windows and macOS filesystems are case-insensitive; a tree containing both `A.md` and `a.md` can therefore be complete in Linux CI but collapse to one physical working-tree entry elsewhere.

The preprocessor rejects collisions before destructive/generated checkout and materialization. The same validator covers committed active trees, dirty/live tracked membership, editable themes, and the merged active+sibling tree. Equal normalized leaf paths and file/directory aliases are rejected. Case-only directory spellings such as `Foo/a` versus `foo/b` are allowed when the descendant leaves remain distinct, matching native Git-for-Windows behavior.

The comparison key uses canonical Unicode normalization plus Unicode lowercase, and is intentionally a conservative portability contract rather than an exact emulator for one filesystem. It does not claim to detect every Windows-invalid/reserved pathname rule. Non-UTF-8 tracked paths are rejected because they cannot satisfy this cross-platform contract.

Case-only renames are not falsely rejected once the old path has actually left the effective tracked working-tree membership. The POSIX regression proves universal Linux-side rejection and live recovery; a separate native Git-for-Windows reproduction confirmed that an unguarded `A.md`/`a.md` tree clones with a collision warning, exposes only one physical file, and immediately appears modified. Native Windows/macOS runtime acceptance remains a separate platform gate.
